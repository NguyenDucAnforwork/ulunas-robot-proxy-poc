# pybench — Python/PyTorch vs C reference latency benchmark

Ad hoc benchmark scripts (not part of the production build) answering: how much faster is
the runtime-free C engine (`mobile/c_neon/src/ulunas_full.cpp`, unmodified, no BN-folding
or other optimization) than the streaming PyTorch reference it was ported from? Full
write-up: `../PYTHON_VS_C_BENCHMARK.md`.

## Files

- `dump_input.cpp` — generates the deterministic input both languages consume
  (`input_pcm.bin`, `input_spec.bin`; seed=1234, uniform[-0.2,0.2], same convention as
  `../src/benchmark_latency.cpp`), so cross-language parity is a byte-identical-input
  comparison rather than relying on replicating C++'s RNG in Python.
- `harness_e2e.cpp` / `harness_model_only.cpp` — same API calls and timing mechanism
  (`std::chrono::high_resolution_clock`) as `../src/benchmark_latency.cpp`, reading from
  the dumped input file and also writing output for parity checking.
- `bench_python.py` — the PyTorch side: `mobile/onnx_export/ulunas_onnx/stream/
  ulunas_stream.py::StreamULUNAS` (the same streaming reference class already used to
  validate this C code's parity), loaded from the real `F_PROXY_ROBOT.tar` checkpoint
  (matching what `../generated/ulunas_weights.h` was exported from), single-threaded
  (`torch.set_num_threads(1)`), timed with `time.perf_counter_ns()`.
- `parity_check.py` — max abs error / RMSE / NaN-Inf check between the C and Python
  output dumps.
- `results/` — the actual run logs behind `../PYTHON_VS_C_BENCHMARK.md`'s numbers.

## Reproduce

```bash
cd mobile/c_neon/pybench
g++ -O2 -std=c++17 dump_input.cpp -o dump_input && ./dump_input
g++ -O2 -std=c++17 -I../src harness_e2e.cpp ../src/ulunas_full.cpp -o harness_e2e
g++ -O2 -std=c++17 -I../src harness_model_only.cpp ../src/ulunas_full.cpp -o harness_model_only
./harness_e2e && cp output_pcm_c.bin output_pcm_c_run1.bin
./harness_model_only && cp output_spec_c.bin output_spec_c_run1.bin
python3 bench_python.py both   # writes output_pcm_py.bin / output_spec_py.bin
cp output_pcm_py.bin output_pcm_py_run2.bin; cp output_spec_py.bin output_spec_py_run2.bin
python3 parity_check.py
```

Input/output `.bin` fixtures are regenerated by the commands above, not committed
(≈2-4MB each, trivially regeneratable, add no information beyond the logged summary
stats and the parity numbers already in `results/parity_check_output.log`).
